# Known limitations — ASTraCAD Inspect

Written 2026-10-15. Each entry states what is limited, how that was measured or read, what the
engine does instead of papering over it, and the workaround. Nothing here is presented as
"minor" when it can change an engineering answer.

## A. Input coverage

1. **Three input routes, unequal strength** (updated 2026-10-17). DXF (dimension entities,
   geometry cross-check), vector PDF (text only, every row needs review) and scans/images
   (two OCR engines must agree, every row needs review, Windows-only). OCR recall on cluttered
   text is low (3/9 on the synthetic scan); disagreements are escalated, never used.
2. **Modelspace only.** Dimensions are collected from `doc.modelspace()`
   (`dims = [e for e in msp if e.dxftype() in ("DIMENSION","ARC_DIMENSION")]`). Drawing-sheet
   (paper-space) dimensions are not read, and `page_count` is hard-coded to 1
   (`DrawingBundle.page_count: int = 1`). A multi-sheet drawing would therefore be reported with
   one page and only its modelspace content.
3. **Block contents are not exploded.** `INSERT` is in `_GEOMETRY_TYPES`, so a block reference
   contributes to the extents and the census, but dimensions or text *inside* block definitions
   are not traversed. Drawings whose callouts live inside blocks would show as missing
   characteristics — the entity census is what makes that visible rather than silent.
4. **Units must be declared by the file.** `$INSUNITS = 0` raises `UnitError`; the only way
   forward is the explicit `declared_unit` argument (recorded as `user_specified`, never as
   extracted). Verified by `tests/test_ingest.py::test_undeclared_units_stop_the_run`.
   There is no millimetre default anywhere in the codebase.

## B. Engineering notation not supported

5. **ISO 286-2 fit classes resolve only inside the loaded table subset.** `⌀20 H7` yields
   `FitClass(hole="H7")` and `limits = (20.0, 20.021)`. The numbers are not in the code and were
   not typed from memory: they come from `src/astracad_inspect/data/iso286-2.json`, generated by
   `tools/iso286_extract.py` from two published deviation tables (an HTML table pair and an
   8-page PDF table), where **a cell is loaded only if both sources state the same upper and lower
   deviation for the same class over the same nominal size step, that step is one ISO 286-2's own
   Table 1 defines, and the cell's band width equals the IT value Table 1 prints for that step and
   grade**. That leaves 783 cells — 37 hole and 37 shaft classes over the 11 standard steps from
   3 to 400 mm. Dataset, method and exclusions are recorded inside that file's `provenance` block.
   What this cannot do, and what was found on the way:
   * **placing a value is a reading, and this build read it wrong once.** Both tables print a finer
     nominal header (…30-40, 40-50, 50-65…) than the standard defines steps (…30-50, 50-80…), and
     most rows carry one value per step. Reading a row straight onto the header put every value
     above 30 mm one column early: `H7` at 45 mm came back +30 µm, which is the 50-80 step's value,
     where ISO 286-2 states +25 µm. Each cell is now keyed by the width its own cell declares —
     `colspan` in the HTML, the printed x-centre against the header's column centres in the PDF
     (residuals under 0.3 pt) — and a row whose cells do not cover the header exactly is dropped.
     Three independent readings agree on the result: the colspans, the PDF positions, and ISO
     286-2:2010 Table 3, which prints `E6` as +66/+50 over 30-50 mm. The band gate would have
     caught the shift alone, because a row placed one step early carries the next step's IT value.
   * cover every class. Four published rows (`R6`, `R7` holes; `r6`, `a12` shafts) print one value
     per header column instead of one per size step, so above 30 mm they state values for columns
     the standard does not define. Those 58 cells per table are dropped rather than snapped onto a
     neighbouring step; the classes stay loaded to 30 mm and refuse above it.
   * correct a published table. `⌀330 E7` refuses: both tables print +185/+125 over 315-400 mm, a
     60 µm band, where Table 1 states IT7 = 57 µm there. Two tables agreeing because one copied the
     other is not confirmation, so the standard's value decides and the cell is dropped. `F6` over
     30-50 mm is dropped because the sources disagree outright (+2 µm vs +25 µm), and `E13` over
     315-400 mm because only one of them carries it. Choosing a side would be an editorial
     decision, so those classes block.
   * use the ISO 286-1 formula as a gate. `i = 0.45·∛D + 0.001·D` does not reproduce the published
     IT series (16i = 24.03 µm at the 30-50 step is published as IT7 = 25 µm, and 100i = 130.75 µm
     is published as 130 µm), so it cannot validate a cell and is recorded as a note, not a check.
   * resolve a fit *pair*. `⌀10 H7/g6` names a hole and a shaft in one callout; one characteristic
     is one feature, so neither side is adopted and the row blocks. The plate fixture keeps such a
     row precisely so the gate stays visible.
   * cross a unit system. The table is millimetric, so `0.7874 H7` on an inch drawing is refused
     rather than converted.
   The standard is not redistributed: `_sources/iso286-2-sample.pdf` is a watermarked preview copy,
   read only to check the size steps and IT bands, and no value taken from it ships in the JSON —
   which records the copy's path, sha256 and that licence note in `provenance.checked_against`.
   The three files the shipped values *do* come from are unverified as to redistribution rights
   (two print `&copy; 2020 Roymech.org` with no grant, one prints no notice at all); that is
   recorded as an open checkpoint in `docs/licences/dependency-licences.md` §6, not assumed safe.
   Anything refused keeps `limits = None` and a blocking reason. Inventing a value for an absent
   cell would be a fabrication.
6. **Thread designations are preserved, not converted.** `M8-1.25` is recorded with the note that a
   thread is not a size dimension and no limits are claimed. `M8-6H`, `M12x1.25` and `1/4-20 UNC`
   are *not* recognised as threads by the current grammar and escalate as unrecognised annotation
   text — same safe outcome (blocking, no numbers), but a less specific reason. An inch thread
   callout can also leave a spurious nominal behind in the parse (`1/4-20 UNC` reads `1.0`); the
   row still blocks and no limits are claimed, and it is escalated rather than silently dropped.
7. **GD&T is partial** (updated 2026-10-17). Feature control frames are read from DXF
   `TOLERANCE` entities and from Unicode frame text (PDF/OCR): symbol, zone, ⌀ zone, MMC/LMC/RFS,
   datums; limits are 0..zone. MMC/LMC bonus tolerance is not computed (flagged per row), datum
   feature symbols are not linked to features, composite-frame semantics are not evaluated
   (each row stands alone), and frames drawn as graphics in a PDF are missed.
8. **Title-block extraction is partial.** Part name, material and a labelled revision are
   recognised from titled text; when no drawing number is found the record says
   `"_note": "no title-block drawing number recognised; recorded as absent"` rather than guessing
   one. Revision is taken from the drawing when the drawing states it, otherwise it falls back to
   `A` **and is labelled as that fallback** (`revision_source = "default - the drawing states no
   revision; confirm before issuing"`, plus a warning that reaches the report's Limitations list).
   Label matching is opportunistic text scanning: a title block drawn as anonymous text pairs, or
   inside a block reference, is not parsed (see 2 and 3).
9. **Surface finish symbols, weld symbols, and section views** are not modelled at all.

## C. Geometric verification

10. **The cross-check only covers rows whose callout states a single nominal.** On
    `plate_synthetic`, 9 of 10 characteristics are checkable against geometry
    (`geometry_cross_checked=9`, all 9 agreeing). The tenth is the limit pair `⌀10.05/10.00`: two
    limit sizes are not one value the drawn distance can agree or disagree with, so its check is
    `NOT_VERIFIABLE` with the reason "the callout states no single nominal" — it is checked by rule
    only, and `geometry_cross_check_coverage` reports exactly that count. A repeated-feature count
    row (`2X ⌀20 THRU`) *is* checkable, because its size is a nominal. Both facts are pinned by
    `tests/test_ingest.py::test_a_limit_pair_leaves_the_geometry_with_no_single_value_to_agree_with`.
    Escalated free text (`86.98 87.05`) can never be cross-checked — which is precisely why it is
    escalated and not accepted.
11. **Cross-check compares a written value against the drawn distance, not against a full model
    tolerance.** It detects "the callout cannot be satisfied by this geometry" (the
    `90 ±0.1`-drawn-at-100 fixture blocks while its `20 ±0.1` neighbour passes). It does not
    validate whether the drawing is *well-constrained*.
12. **Balloon placement is a lattice, not a human layout.** Slots are pre-separated so balloons
    cannot overlap by construction, and leaders that would cross the part are rejected and moved.
    The result is unambiguous and deterministic, not aesthetically tuned. Radius is fixed at 4.0
    with gap 2.0 and margin 14.0 in drawing units; a drawing whose extents make those sizes wrong
    will report unplaced balloons (`balloon_unplaced`) instead of quietly overlapping.

## D. Numbers and their honesty

13. **Derived limits are rounded to 9 decimals.** `25.4 - 0.1` stores as
    `25.299999999999997` in binary floating point; `_round_limit()` cuts that representation error
    (a nanometre — below any tolerance zone a drawing can state). Limit pairs copied from a
    callout are **not** rounded: they are returned exactly as written. Rounding is documented in
    `limits.py` rather than hidden in the formatter.
14. **Duplicate callouts are flagged, never merged.** Two characteristics with identical
    kind/nominal/limits raise a `possible_duplicate_callout` *warning* (visible on
    `plate_synthetic` rows CH-007/CH-009) because a genuinely repeated dimension is legal. Merging
    would silently delete a feature that an inspector must measure twice.
15. **Every metric in a report carries its denominator.** Coverage is reported as
    `dimensions=9 extracted=9 resolved=8 unresolved=1 blocked=1 geo_checked=8/8 …`, and
    `extraction_rate` excludes reviewer-stated rows from the numerator so a manual addition cannot
    inflate the extraction figure.

## E. Test and evidence limits

16. **All labelled fixtures are SYNTHETIC.** Both were machine-generated by
    `tools/make_fixtures.py`. The measured results (recall 1.0, strict field accuracy 1.0,
    precision 1.0 over 12 labelled characteristics, 38/38 reopen checks) describe **this code
    path on this dataset only**. They are not evidence about real production drawings, and no
    report should quote them without the accompanying `limitations` block written into
    `_out/regression_report.json`.
17. **Fixture regeneration is not byte-reproducible.** Two runs of `make_fixtures.py` on the same
    source differ in exactly 10 lines of 10058: ezdxf writes creation/update timestamps (Julian
    and ISO), two random `FUUID`s, and reorders two dictionary entries (`ACDBPLACEHOLDER` /
    `LAYOUT`). Consequence: a SHA-256 pins *the file that was actually run*, never "the fixture
    concept". The regression contract is the label JSON, and the checked-in `.dxf` bytes are
    treated as the reference input.
18. **The label file is hand-maintained.** The harness checks escalations in both directions (a
    labelled escalation must not become a row; an unlabelled escalation is reported as
    `unlabelled_escalations`), but it cannot detect a characteristic the label author forgot to
    record at all. The entity census is the backstop, not the metrics.
19. **No real-drawing benchmark exists.** Until a customer-supplied drawing set is labelled,
    accuracy on production content is unknown — genuinely unknown, not assumed to be good.

## F. Environment and integration

20. **`%TEMP%\pytest-of-solid` is inaccessible on this PC** (`WinError 5`, even for `icacls`)
    while generic temp creation works. pytest is rooted inside the project via
    `addopts = ["--basetemp=.pytest_tmp"]`. This is a workaround for a machine defect, not a
    portable requirement.
21. **Unicode output on a legacy console is replaced, not crashed.** `cli.main()` reconfigures
    stdout/stderr with `errors="replace"`, because a check that cannot print its detail line was
    previously aborting a *passing* selftest with exit 1 on this PC's cp1252 console
    (`tests/test_cli.py` covers it). The consequence is cosmetic: ⌀ can come out as `?` on such a
    console. Scripts that print directly, without going through the CLI, still want
    `PYTHONIOENCODING=utf-8`.
22. **Upstream deprecation:** ezdxf 1.4.4 sets `.shape` on NumPy 2.5 arrays, producing 2
    DeprecationWarnings per test run. Recorded, not filtered out of the output.
23. **No git repository** exists in this workspace, so there is no commit-level provenance; the
    SHA-256 run records are the only integrity trail. `git init` has not been run (unauthorised).
24. **PyMuPDF (AGPL-3.0) is now optional** (2026-10-17): the run time declares pypdfium2; PyMuPDF
    is only the `table-rebuild` extra and a fallback if pypdfium2 is missing. A release must ship
    pypdfium2 and should drop the fallback. See `docs/licences/dependency-licences.md`.
25. **The `.NET` CAD backend is untouched.** `mecagent-alternative` and its SolidWorks interop
    exist on this machine, but ASTraCAD calls nothing outside Python; there is no STEP/SLDPRT
    ingestion and no geometry generation.

## G. What is *not* a limitation, stated explicitly

The gate cannot be turned off; there is no flag that marks an unresolved plan as releasable. A
reviewer exception requires a name in the override document and is reported as
"releasable with N accepted exception(s)" with the exceptions still listed. Tests have not been
weakened to reach green (§XVI): every failure found this session — a stored nominal colliding
with a limit pair, three checks that printed failure-worded `actual` strings while passing, an
`ink_fraction` measurement that was trivially true because of float images, a ⌀ glyph silently
substituted by Helvetica — was fixed in the product or in the verification, and each fix is
covered by a check that now fails if it regresses.

## Added 2026-10-17

- **Revision comparison** pairs features by kind + extents-normalised definition points + measured
  geometry. Two features of the same kind at nearly the same place are reported AMBIGUOUS, never
  guessed. Verified on synthetic revisions only (including a whole-sheet shift of (300, −120)).
  Free-text notes are compared as exact strings.
- **Tolerance engine**: 1-D linear stacks only (no 2-D/3-D vector loops, no GD&T zones). RSS and
  Monte Carlo need the user to state k and distributions; there are no defaults. ISO fits use the
  same 3–400 mm table subset as inspection.
- **Request interpreter**: deterministic patterns for blocks/plates (optional through hole) and
  cylinders/shafts, plus detection of "change <dimension> of my model" (reported as missing the
  document and the named dimension). "60 x 40 x 20 mm" applies the trailing unit to all three values.
- **SOLIDWORKS adapter**: creates new parts only; cannot open or edit an existing file; no revolve,
  pattern, shell, assemblies or drawings. Independent STEP volume is computed only for
  polyhedra — curved solids report `not_verifiable` (the kernel's own volume check still runs).
  `mac`'s through-all hole check passes with its own ~2 ppm allowance, stated in its report.
- **Creo / Fusion / AutoCAD**: not installed on the PC; adapters only discover and report state.
  No operation is implemented, and none will be marked supported until run on the real application.
- **Authorization** on the CLI is a self-asserted name (`--authorize KM`); adequate for a
  single-user desktop tool, not for multi-user deployment.
- **Editing existing parts** changes named driving dimensions only, always on a copy written to the
  authorised directory; the source hash is checked before and after by both `mac` and Python. A
  plain-language word ("diameter") is never mapped to a dimension automatically — the full name
  (e.g. `D1@Sketch1`) is required. Configurations, equations and global variables are not handled.

## Added 2026-10-17 (drawing route)

- **Drawings are minimal**: three standard views and model dimensions; no sheet format, title block,
  tolerances, sections or notes. Parts only (no assemblies).
- **Educational SOLIDWORKS licence** on this PC: generated sheets are watermarked for instructional use only.
  Nothing produced here may be presented as commercial output.
- **One unexplained hang**: a drawing run blocked inside SOLIDWORKS once (Model Items prompt left active);
  recovery needed Esc and a SOLIDWORKS restart. Not reproduced since. The adapter now turns a timeout into a
  FAILED task with recovery advice.

## Added 2026-10-17 (costing)

- **One cost model**: a part machined from a rectangular block (bbox + allowance). Turned parts from bar,
  castings, sheet metal and multi-operation routings are not modelled. Cycle time is given, or derived from a
  user-stated MRR; no CAM-based time. Fixturing, tool wear, finishing, inspection and logistics are excluded.
- **No prices are shipped.** The example rate book is placeholders labelled EXAMPLE; real use needs the
  user's own sourced, dated figures. Inputs older than 90 days are flagged, not refreshed.

## Added 2026-10-17 (general tolerances)

- ISO 2768-1 values are transcribed from widely reproduced tables, not read from a licensed copy of
  the standard; verify before acceptance use. Angular general tolerances are not applied (need the
  shorter leg length). ISO 2768-2 (geometrical, H/K/L) classes are recorded in the note but not applied.

## F. Web workspace (2026-10-17 redesign)

- Sheets and layout pages are rendered for up to 12 pages; balloons on later pages fall back to
  ring placement and are not shown on a sheet.
- The DXF sheet is ezdxf's rendering: dimension text is drawn at its true (often small) size, so it
  needs zooming to read. The callout itself is always shown in the list and inspector.
- Runs made before the interactive sheet get one rendered on first view, only when the source
  drawing is byte-identical (SHA-256); otherwise the static layout image is shown, and says so.
  Their balloons keep the layout they were issued with (ring style) until re-run.
- Adjacent placement needs the callout's text box: DXF from the dimension's own geometry block,
  PDF from the text run, scans from the OCR region. A DXF dimension without a geometry block, and
  ring-placed balloons, point at the feature anchor instead.
- Reading order is by bands of 1/8 of the sheet height; two callouts straddling a band edge can read
  in the "wrong" band. Numbers are always unique and stable for the same drawing.
- Item-balloon detection (PDF) can take a dimension printed inside a tight empty circle for an item
  balloon (one case on the 18-sheet corpus); the census names how many were skipped as balloons.
- The UI was checked in a Chromium-based pane at 1440×900, 1024×768 and 375×812 (touch emulation);
  not checked in Firefox or Safari, and not with a screen reader.
- The design method (UI UX Pro Max) has no manufacturing-inspection category; the nearest rows were
  combined — see `docs/design-system/MASTER.md`.

## H. Text → CAD (2026-10-17)

- Shapes: block / plate, cylinder / disc / flange, stepped shaft, tube / washer / spacer, plus through holes
  (one, a straight row, a bolt circle) in the front face. No fillets, chamfers, threads, slots, pockets,
  blind holes, counterbores or features on other faces; such words are not read and the request still
  builds without them only if nothing in it is missing - check the facts table, which lists what was read.
- Patterns are interpreted from fixed phrasings ("4 x 6 mm holes at 20 mm pitch along the width,
  centred", "6 x 10 mm holes on a 90 mm PCD starting at 30 deg"). Anything else is reported missing.
- Bolt circles are built as N separate hole features (`mac` has no circular pattern), so a later edit of
  the hole size touches N dimensions.
- On a round part the start angle of a bolt circle is AI_PROPOSED (0°) without blocking the build, because
  it does not change size or volume; it does change where the holes are. Say "starting at A deg" if it matters.
- Only SOLIDWORKS executes. Builds run one at a time in the workspace; the page waits for the build
  (about 10-60 s) and a second build is refused, not queued.

## G. Measurement results (2026-10-17)

- Tabular CMM and gauge export files (CSV/XLSX) are imported via `astracad_inspect.import_results`
  with preview/commit gates, SHA-256 and row-level traceability, and saved CMM mapping profiles per program
  (with case-insensitive fallback). Vendor-specific binary CMM report formats (PC-DMIS `.cad`/`.pcd`,
  Calypso `.chr`/`.dfq` binary) are not parsed natively — files must be exported as tabular CSV/XLSX.
  Values can also be typed manually by the inspector. The instrument register is enforced once it has an entry;
  while it is empty, instrument IDs are free text and flagged.
- Calibration is judged by the due date alone (no certificate verification, no measurement
  uncertainty); the 10:1 rule is a rule of thumb shown as a warning, not a decision rule.
- Values are converted between inch and mm if needed with original preserved; unrecognized units are refused.
- Cp/Cpk from a few samples is an indication only; the label states n. No control charts.
- GD&T rows are judged as a measured deviation against 0..zone; MMC/LMC bonus is not applied.

## I. Quality dossiers (2026-10-17)

- **Project-level quality dossier**: aggregates all runs in a project folder. If a run has multiple samples, each is checked; an empty project cannot build a dossier. Drawing sources modified outside ASTraCAD are excluded from the sources/ folder with a note in the manifest and PDF rather than halting the dossier generation.
