## M2 — real drawing corpus (highest priority; blocks every accuracy claim)

Not started. Today's 1.0 scores are on **synthetic** fixtures only, so accuracy on production
content is unknown.

- Acquire 5–20 real drawings with owner permission (constitution §XVII: no external upload).
- Label each with `tools/make_fixtures.py`'s label schema — human-labelled ground truth, reviewed.
- Add `tools/annotate_fixtures.py` so the labelled-vs-extracted diff can be reviewed visually.
- **Exit criteria:** per-drawing recall / field accuracy / precision reported with denominators;
  every miss explained as one of: notation unsupported, geometry unread, parser bug. No aggregate
  may be published without the per-drawing table.

## M3 — GD&T and tolerance-table support

**ISO 286-2 fit classes: delivered.** `⌀20 H7` resolves to 20.000–20.021 from
`src/astracad_inspect/data/iso286-2.json` — 783 published cells, 37 hole and 37 shaft classes over
the 11 nominal size steps from 3 to 400 mm — generated by `tools/iso286_extract.py` from two
independent published tables and checked against ISO 286-2's own Table 1: a cell is loaded only if
both tables state the same deviations over the same step **and** the band that results equals the
IT value Table 1 prints for that step and grade. Two cells were dropped on those rules (one
published `R6` band contradicts its own grade in both sources; `E7` over 315-400 mm is published
with a 60 µm band where the standard states IT7 = 57 µm), so an absent class stays unresolved and
blocks rather than being corrected by hand. `feature_support` now states the loaded subset instead
of a blanket refusal.

Still not started: `feature_support` declares `gdt.feature_control_frame`, `gdt.datum_reference`
and `surface_finish_symbol` as "NOT supported in this milestone", and a thread designation left
unresolved.

- Feature control frames: geometric characteristic, tolerance zone, material condition, datum
  references — a new `CharKind` family with its own measurement methods in the suggestion table.
- Datum identification and the feature-to-datum link, so an inspection method can cite the datum
  scheme rather than invent one.
- **Exit criteria:** a labelled drawing with frames + fit classes reaches recall 1.0 with zero
  invented limits; every unresolved notation still blocks rather than defaults.

## M4 — input breadth: PDF drawings, raster, OCR-assisted

Not started, and deliberately kept out of M1 so no number ever came from a pixel guess.

- `ingest/pdf.py` and `ingest/raster.py` producing the same `DrawingBundle`.
- OCR output enters with provenance state `ai_proposed` or `unresolved` — never `parsed`, because a
  recognised glyph is not a read dimension. Escalation thresholds must be explicit.
- **Exit criteria:** a drawing with no vector text produces a plan whose coverage statement says
  plainly how much came from OCR and how much was refused.

## M5 — CAD backend integration (the Ω in ASTraCAD Ω)

Not started. `mecagent-alternative` (`mac`, .NET 10, SolidWorks interop) exists on this PC but
nothing in ASTraCAD calls it.

- `backend/mac_adapter.py`: JSON contract across the runtime boundary; ask the kernel for measured
  geometry, then cross-check the plan's limits against the model.
- Respect the recorded environment quirks: two SolidWorks properties silently return wrong values
  on this install, and CAD artefact hashes differ run to run — so re-read and compare values, never
  timestamps.
- Machine-control operations stay out (§XV): this milestone reads and verifies, it does not actuate.
- **Exit criteria:** a plan validated against a 3D model's measured dimensions, with any
  model-vs-drawing disagreement blocking the gate.

## M6 — interactive correction and review UI

Not started. Corrections currently flow through a JSON override document.

- A review surface over the *same* override schema — one correction channel, so the audit trail
  cannot fork.
- Named reviewer, per-change attribution, and a refusal path that keeps the finding visible
  (`geometry_disagreements_accepted_by_reviewer` stays as an accepted exception, never as a pass).
- **Exit criteria:** a reviewer can resolve a blocked plan end to end and the resulting PDF names
  that reviewer and their changes.

## M7 — distribution hygiene and release gate for the tool itself

Open items that block any external release:

1. **PyMuPDF AGPL-3.0 decision** (keep + AGPL, buy the commercial licence, or swap the reopen route
   to a non-AGPL reader and re-measure). See `docs/licences/dependency-licences.md` §2.
2. Wheel-hash pinning in `requirements.lock` (needs a network fetch, not yet authorised).
3. Version-controlled workspace: `git init` and a first commit are **awaiting the user's explicit
   instruction** — nothing in this session has been committed.
4. CI that runs `py -m pytest -q`, `py -m astracad_inspect selftest` and `py tools/regression.py`
   with their documented exit codes.

## Deliberately deferred, and reported as absent rather than stubbed

Multi-sheet/paper-space ingestion, block content traversal, revision comparison, weld and surface
symbols, tolerance stack-up analysis, CMM program output, statistics/SPC, and any model-assisted
interpretation. None of these has a fake module behind it: the constitution forbids building
incomplete modules to make the interface look feature-rich (§VI), and `doctor` / the
`feature_support` table state what exists today.

## Standing commands

```
cd astracad
py -m pytest -q                      # 153 passed on 2026-10-15
py tools/regression.py               # metric harness, exit 0 = targets met on the labelled set
py -m astracad_inspect selftest      # 34/34, no drawing required
py -m astracad_inspect run tests/fixtures/plate_synthetic.dxf --out _out    # exit 3: delivered, NOT releasable
py -m astracad_inspect doctor        # environment and route availability
py tools/iso286_extract.py           # rebuild data/iso286-2.json from _sources/ and re-run its
                                     # three gates; refuses to write if a gate cannot be checked
```
(`py -m astracad_inspect` needs `PYTHONPATH=src` until the package is pip-installed; the pytest
config already puts `src` and `tools` on the path.)
